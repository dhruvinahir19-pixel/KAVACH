§0Purpose & How to Use This Document

This document is the single source of truth for the KAVACH-945 system. It is written so that if every chat log, note, and workspace file were lost tomorrow, a competent developer (or you, with patience) could rebuild the entire engine from scratch — data ingestion, feature panel, model, walk-forward validation, direction prior, morning protocol, sniper rules, stop-loss simulator, backtester, and every audit — using only what is written here.

The project began with a report describing a next-day mover engine; that report was reverse-engineered into a working system, then extended stage by stage through six stages of research, each stage's decision forced by evidence. This document supersedes everything that came before it.

Reading order for a rebuild

§3 (data) → §4 (selection) → §11 (file map & commands) in one pass; then §5–§9 for the trading rules; §10 tells you which bugs have already been made and fixed so you don't repeat them. §12 is the daily routine. Appendix C is the one-page constants card to keep next to the terminal.

What this document is not

It is not a promise of returns. Every number inside is a backtest on 18 out-of-sample months (Apr 2025 – Sep 2026) with modeled costs. The system has never traded live. The final gate (§13) is forward paper-trading, and it has not been passed yet. The Monte Carlo verifies the arithmetic and geometry; it cannot verify that the edge persists.

§1System Identity, Philosophy & Constraints

THE NAME

KAVACH-945 — Kavach (कवच) is Sanskrit for armor. The defining innovation of this system is not its winners — it is its refusal to die on its losers: a hard 1% disaster stop that bounds every trade at −1.2% and every trading day at approximately −4.8% of the book. 945 is the minute of the morning reveal — 9:45 IST — when the evening's preparation meets the market's first verdict and the trade is either confirmed or discarded.

Core Identity Evening intelligence · Morning confirmation · Armored execution. Select tonight, confirm at 9:45, armor every trade, exit by 15:10.

§2Architecture — The Six-Layer Stack

KAVACH-945 is a pipeline of six independent layers. Each layer was validated alone before the next was built on top of it. In production, layers 1–2 run after the evening close, layer 3 fires at 9:45 the next morning, and layers 4–6 are the execution discipline wrapped around the trade.

1 · SELECT
Evening: gradient-boosted model scores every F&O-universe stock for "tomorrow's top-quintile mover" probability → Top-10 watchlist
→
2 · TILT
Evening: futures basis z-score per pick → directional prior (discount = bearish lean, premium = caution on longs)
→
3 · REVEAL
9:45 next morning: price vs 9:15–9:30 opening range → LONG above OR high, SHORT below OR low, else no trade
4 · SNUFF
Same 9:45 moment: if a side has >3 confirmed candidates, keep only the 2 calmest (20-day range) — correlation control
→
5 · ARMOR
On fill: hard bracket stop 1.0% adverse from entry. Every trade. No discretion. Bounded loss = −1.2% incl. costs
→
6 · EXIT
15:10 manual exit if not stopped (avoids broker auto square-off charges). Risk 1% of capital per trade
The one-sentence system

Tonight the engine names ten suspects and leans directional via futures basis; at 9:45 tomorrow the opening range interrogates them and only 1–3 survivors get a ticket — each wearing a 1% armor vest — and everyone goes home by 15:10.

2.1 Signal flow vs data flow

  • Signal flow (per trading day T): EOD data through close of T−1 → model scores for day T → Top-10 watchlist published evening of T−1 → 9:45 on day T: OR confirmation on live quote → entry → stop/exit.
  • Data flow (batch): daily harvest appends EOD stores → features.py rebuilds panel → validate.py walk-forward regenerates OOS predictions → morning.py rebuilds the joined morning table → protocol_v2.py produces the backtest book.

§4Layer 1 — Selection Engine ("MFE v2", the mover model)

Goal: every evening, rank the F&O universe by the probability that each stock will be a top-quintile mover tomorrow, and publish the Top-10 as tomorrow's watchlist. This layer says nothing about direction — only "will move".

4.1 Label (what "mover" means)

next_tr_pct  = 100 * (max(next_high, close) − min(next_low, close)) / close     # tomorrow's true range as % of today's close
y_move       = 1 if next_tr_pct >= 80th percentile of that DAY's cross-section   # QUINTILE = 0.80
base rate    ≈ 0.202  (20.2% of stock-days are "movers" — by construction ~top 20%)

The label is cross-sectional per day (top quintile of that day's universe), so the model learns "unusual mover for tomorrow's tape", not an absolute % threshold that would break across regimes.

4.2 Features — 57 columns, all strictly ≤ close of day T

Discipline: every feature at row (t, stock) uses ONLY data up to the close of t. Ratios vs "20-day average" use the mean of the PRIOR 20 sessions (today excluded) so a surge is not diluted by itself. Labels use t+1 data only.

Key constructions: atr14 from true range (h−l, |h−pc|, |l−pc| max) with min_periods 10; vol_ratio = volume ÷ prior-20d mean; basis_pct = near-month futures vs cash; options aggregated to per-stock OI/volume PCR + top-3 strike OI concentration; participant nets from the nsccl file. All rolling stats are per-symbol groupbys with shift(1) where "prior" is meant.

4.3 Ranking, model, and walk-forward protocol

# 1. Cross-sectional rank: every feature → its percentile within the DAY
rank_features(p):  r[f] = p.groupby("date")[f].rank(pct=True)     # for all 57 features

# 2. Model (exact hyperparameters):
HistGradientBoostingClassifier(max_iter=250, learning_rate=0.06, max_depth=4,
                               min_samples_leaf=60, l2_regularization=1.0,
                               random_state=42)

# 3. Walk-forward (the anti-leakage core):
months = all calendar months in panel
first 3 months  → initial training pool ONLY (never scored)
every later month m:  train on ALL rows with month < m  →  predict month m  →  OOS
per day: top-10 by prob = the watchlist; hit rate = mean(y_move of top-10)
walk-forward hit rate  =  mean over OOS days of daily top-10 hit rate
Why this is leak-proof by construction

The model that scores day D has never seen any row from D's month or later. Features are day-cross-sectional ranks, so a feature can't smuggle information across time. The physically-destructive test: re-scoring 2025-08-29 with the full panel vs a panel truncated at 2025-08-29 produced identical probabilities to 0.00e+00 across all 209 scored stocks (§10).

§5Layer 2 — Direction Prior (futures basis)

Goal: after selection says "this stock will move", tilt the expectation up or down. Two candidate mechanisms were tested; one was rejected on evidence.

5.1 REJECTED — the a-priori trap scorecard

Rejected after testing

A v1 scorecard of a-priori weighted trap signals (failed breakouts, exhaustion gaps, OI divergence signs...) and a v2 refit of sign-per-feature. Rejection reason: regime fragility — fitted signs flipped between halves of the sample; fade/contrarian rules lost at every horizon. If a direction rule's coefficients depend on which half-year you fit it on, it is not a rule. Do not rebuild this.

5.2 VALIDATED — futures basis discount prior

basis_pct = (near-month futures price − cash price) / cash price          # per stock-day
# per-symbol 20-day rolling, then SHIFTED (prior window excludes today):
_bm = rolling20_mean(basis_pct)  → shifted 1
_bs = rolling20_std (basis_pct)  → shifted 1
basis_z = (basis_pct − _bm_shifted) / _bs_shifted

prior = −1  if basis_z ≤ −1.5     # deep DISCOUNT → bearish lean
prior = +1  if basis_z > +1.5     # deep PREMIUM → (see 5.4 caution)
prior =  0  otherwise

OOS finding (2026 window, n=145 pick-days): picks carrying basis_z ≤ −1.5 closed DOWN next day 62.1% of the time (range across windows: 62–66%), average move −1.14% close-to-close.

5.3 Decomposition — where the basis edge actually lives

Finding: the basis prior is an OVERNIGHT lens, not an intraday filter

Of the discount-day −1.14% average: ≈ −0.45% is the overnight gap, and only ≈ −0.25% remains from 9:45→15:10. Consequences that shaped the system:

  • Basis discount works as positional/overnight context (why we lean short, why we're wary of longs on discounted names) — NOT as an intraday entry filter.
  • Tested as a morning filter (skip OR-up longs on discounted names): win rate 69.4% vs 69.9% — no effect. The morning tape overrides the evening prior.
  • Override finding: SHORT ★★-prior picks whose 9:45 tape is UP → 58.8% continued up. The 9:45 confirmation outranks the basis prior every time.

5.4 Premium observation (unvalidated, small n — noted, not a rule)

Observation PREMIUM picks (basis_z > +1.5) made the weakest OR-up longs in the 2026 window: 53.8% win, +0.15% avg (n=26) vs neutral-basis 72.2% / +1.10% (n=144); discount × OR-up was 75.0% (n=16). Interesting, counterintuitive, too small to act on. Carried as a watch-item for the paper-trading log.

§6Layer 3 — The 9:45 Morning Reveal

Goal: convert "will move" + "leans down" into an actual intraday entry with a structural trigger — no indicators, just the market's first real verdict.

6.1 Exact time windows (all IST, from 5-min bars)

WindowClockBar minute-of-day (mod)Meaning
Opening range OR159:15 – 9:30555 – 569Range high/low = or15_h / or15_l
Confirmation bar9:30 – 9:45570 – 584c945 = close of the LAST bar in this window (the 9:40–9:45 bar) = entry price

Convention trap (documented bug class)

"15:10 exit" means the last bar whose START minute ≤ 15:10 — not the last bar ending before 15:10, and not the 15:25 close. All stages use between(585, 910) on bar-start minutes. Any simulator that deviates will disagree with the morning table on ~30% of trades by the 15:10–15:15 bar's return.

6.2 Rules

LONG : evening Top-10 pick  AND  c945 > or15_h    → buy at c945, exit 15:10 (or stop)
SHORT: evening Top-10 pick  AND  c945 < or15_l    → short at c945, exit 15:10 (or stop)
no breakout (or15_l ≤ c945 ≤ or15_h)              → NO TRADE in that stock
costs: COST = 0.15% round trip on every trade (brokerage + STT + slippage estimate)
rod_ret = rod_c / c945 − 1        # rest-of-day return from the 9:45 entry

  • Max losing streaks: 8 trades both sides. Worst trades: long −11.07%, short −9.71%.
  • Per-day P&L (1× each side): +1.50%/day average, 57% win-days, worst day −21.39% (2025-12-09: six correlated longs — AMBER −5.25, PGEL −6.89, GODREJPROP −4.56, KALYANKJIL −2.60, BSE −1.89, COFORGE −0.19 — on a gap-down tape), best day +31.15%.
  • Combined 1×long/0.5×short: +407pp, +1.18%/day, 60% win-days, worst day −15.25%.
  • Same-day control (18 months): all OR-up stocks 46.4% / −0.10% vs picks 61.9% / +0.60%.

→ One correlated morning could erase a month of profit. This is the problem the KAVACH armor solves (§8).

§8Layer 5 — The KAVACH Armor (Sniper Protocol v2)

User spec, verbatim intent: trade only 1–2 best stocks a day; disaster SL so no morning wipes weeks of profit; keep quantity — no filters that reduce trade days; only filter a side when MORE than 3 stocks are picked for breakout or breakdown.

  LONG side candidates : c945 > or15_h          SHORT side candidates: c945 < or15_l
  PER SIDE:  n ≤ 3  → trade ALL of them

8.2 Why range20 is the ranker (the "deeper stock selection")

Every signal legitimately available at 9:45 was tested as a within-day ranker (breakout margin, OR width, aligned gap, model prob, basis_z, v45_ratio, 20d-range breakout freshness, stop distance, range20). Honest headline: no feature reliably separates "best" from "rest" within a day — the top-ranked underperformed the rest in 2025 and overperformed in 2026. The per-trade edge is roughly homogeneous across confirmed candidates, so the cap itself is the protection and the ranker should be chosen for risk, not hoped-for alpha.

9.5 The random-watchlist control (the bug/look-ahead detector)

Control result — 11.4σ separation

60 random 10-stock watchlists per day (drawn from the same universe, same dates) were pushed through the identical pipeline: OR confirmation → >3 cap → range20 top-2 → same costs, no SL (same measure as the raw book). Random control: −0.142% ± 0.046% per trade. Real book, same measure: +0.376%. Z-score: 11.4σ.

Why this matters: a sign error, cost omission, or accounting bug in the pipeline would lift the control's average too — the control shares all the machinery. Only genuine selection edge can separate the two distributions by 11 standard deviations. This is the strongest single piece of evidence that the edge is real within this data.

10.2 Methodology principles (the "no free lunch" list)

  • Selection/validation discipline: ranker (range20) and SL level (−1.0%) chosen on 2025-04→12, validated on 2026-01→09, only then reported on the full window. Split-period validation protects against overfitting but is not proof — that's paper-trading's job.
  • MC uses day-blocks, never trade-iid — same-day trades correlate; iid understates drawdown.
  • Descriptive vs tradeable regime splits — a "regime" that uses same-month information is storytelling; only prior-information splits are tradeable.
  • Rejected on evidence: trap scorecards (sign flips), fade/contrarian rules (lose at every horizon), basis as intraday filter (edge is overnight), forced no-confirmation trades (33% win).
  • Small-n observations carried, not acted on: premium-pick long weakness (n=26), VIX tilt (fit on this sample).

§12Daily Execution Playbook (the operator's card)

EVENING (after ~19:00, data posted)
  1. python3 harvest.py / scanner.py
  2. Read tonight's Top-10 watchlist (with prob, basis_z, prior, range20).
  3. Mark basis leans: discount (z≤−1.5) = bearish lean; premium (z>+1.5) = long caution (§5.4).
  4. Pre-compute range20 ranking for tomorrow. Note OR15 will only be known live.

MORNING 9:15–9:45 (live)
  5. Watch the 10 names' first 30 minutes. No orders before 9:45. None.
  6. 9:44: for each pick note price vs forming OR high/low.

9:45 — THE REVEAL
  7. LONG candidates: price > OR15 high. SHORT candidates: price < OR15 low.
  8. Per side: ≤3 candidates → all; >3 → the 2 SMALLEST range20.
  9. Enter at market ≈ 9:45 close, WITH bracket stop 1.0% adverse. Same minute. (§9.1: 5 min late = −4% edge)
  10. No confirmation on any name → no trades today. Accept. (Forced trades: 33% win, −2.09% avg.)

INTRADAY
  11. Stops are not negotiable. A stop-out is a −1.2% cost of doing business (46% of trades).
  12. Expect losing streaks of 7–9 trades. Size so this is noise: risk 1% per trade.

15:10 — EXIT
  13. Exit all remaining positions manually at ~15:10 (avoids auto square-off charges; §9.2).
  14. Log every fill in the paper-trading journal (§13).
Live-vs-backtest gaps to expect
  • Entry slippage: backtest fills at the 9:40–9:45 bar close; live market orders on breaking names may fill a few ticks worse (the 5-minute-latitude test §9.1 bounds the damage of small lag).
  • The 46% stop-out rate will FEEL worse live than it reads. The system's psychology is: many small amputations, occasional big wins (best day +17.55%, best trade +18.80%).
  • Data timing: the evening stack depends on NSE EOD posting (usually by ~18:30–19:00 IST) and Upstox candle availability (same evening).
